# LabNotes — задание ИИ-агенту

## 1. Цель и порядок работы

Реализуй небольшую платформу для публикации учебных практических работ. Автор один: он создаёт инструкции с командами, скриншотами и вложениями. Друзья читают опубликованные работы без регистрации по ссылке или через каталог. Внешний вид вдохновлён Notion; редактор работает с обычным Markdown и по удобству ориентирован на Obsidian.

Это задание на реализацию: создай код, запусти приложение и проверь основной сценарий. Не останавливайся на проектировании. Самостоятельно принимай обратимые технические решения в рамках этого задания. Не запрашивай подтверждение для установки проектных зависимостей, создания файлов и локальных проверок. Соблюдай существующие инструкции репозитория и не перезаписывай посторонние изменения. Деплой в чужие сервисы, покупку домена и регистрацию аккаунтов не выполняй.

У пользователя мало времени: ориентир — первая рабочая версия за одну сессию, примерно два часа, если позволяет среда. Это не повод выдавать макет за готовое приложение или пропускать проверку доступа. Сначала полностью заверши MVP, затем переходи к улучшениям. Если времени не хватает, оставь запускаемый результат и честно запиши ограничения в STATUS.md.

Рабочее название — LabNotes, язык интерфейса — русский. Название сайта настраивается через конфигурацию. Вопросы о цветах, логотипе и названии не должны блокировать работу.

## 2. Фиксированный стек

| Область | Решение |
| --- | --- |
| Бэкенд | Rust stable, Tokio, Axum, tower-http |
| Хранение | SQLite через SQLx, миграции SQL |
| Фронтенд | Svelte, TypeScript, Vite, обычный CSS |
| Редактор | CodeMirror 6 + @codemirror/lang-markdown |
| Markdown-просмотр | markdown-it с отключённым raw HTML + DOMPurify |
| Авторизация | Серверные сессии в SQLite, случайный токен в HttpOnly cookie |
| Файлы | Локальный постоянный каталог, метаданные в SQLite |
| Production | Один процесс Rust раздаёт API и собранный frontend/dist |
| Запуск | Docker Compose; дополнительно инструкция для локальной разработки |

Используй актуальные стабильные совместимые версии, проверь их документацию. Зафиксируй Cargo.lock и npm lockfile. Не используй плавающие latest-теги в итоговом Dockerfile. Node.js нужен при разработке и сборке, но не в runtime-образе.

Не добавляй SvelteKit SSR, React, PostgreSQL, Redis, отдельный Node-сервер, микросервисы или внешние облачные зависимости. Для такого приложения они не нужны. Не пиши собственный текстовый редактор с нуля.

## 3. Обязательный MVP

### 3.1. Каталог и чтение

- Предметы — плоский список. Внутри предмета находятся страницы практических работ; произвольное дерево не требуется.
- Главная показывает предметы и опубликованные работы. Есть поиск по названию и тексту опубликованных работ; достаточно ограниченного SQL-поиска с debounce, без отдельного поискового движка.
- Каждая работа имеет заголовок, предмет, содержимое Markdown, дату обновления и постоянный URL `/p/:id`. Используй UUID, не меняющийся при переименовании.
- Страница чтения отображает заголовки, абзацы, списки, чек-листы, таблицы, ссылки, изображения, цитаты и блоки кода.
- У блока кода есть кнопка копирования с обратной связью; можно обойтись без тяжёлой подсветки десятков языков.
- Оглавление строится по H2/H3. Переходы по якорям работают в SPA.
- Картинки вписываются в ширину страницы; клик открывает увеличенный просмотр с закрытием через Escape.
- На странице доступен список вложений для скачивания. Для крупных образов ВМ автор может вставить обычную внешнюю ссылку.
- Для неизвестных и неопубликованных страниц анонимный запрос получает 404. API каталога и поиска не возвращает черновики.
- Пустые состояния, ошибки, индикаторы загрузки и понятная страница 404 обязательны.

### 3.2. Вход автора

- Только один администратор, без регистрации друзей и управления ролями.
- Начальная настройка через CLI-команду инициализации администратора или переменные окружения при первом запуске пустой базы. В README покажи точный рабочий способ.
- Не поставляй стандартный пароль. Для Docker допустим ADMIN_PASSWORD из локального .env; в .env.example только пустое значение. После инициализации не меняй пароль автоматически на каждом старте. Опиши способ явной смены пароля.
- Пароль хранится как Argon2id-хеш. Хеширование выполняется вне async worker через spawn_blocking. Ограничь параллельные попытки входа и введи простой ограничитель частоты; сессия создаётся только после успешной проверки.
- Cookie: HttpOnly, SameSite=Lax, ограниченный срок; Secure в HTTPS production. Локальный HTTP-режим разрешён только явной настройкой.
- Храни хеш случайного токена сессии, а не сам токен. Logout отзывает сессию и удаляет cookie. Просроченные сессии не принимаются.
- Авторизованный режим показывает черновики и административные действия. Скрытие кнопок не заменяет проверку авторизации на сервере.

### 3.3. Управление материалами

- Создание, переименование и удаление предметов. Предмет с работами не удалять молча: вернуть понятную ошибку, предложить сначала переместить или удалить работы.
- Создание работы, редактирование заголовка и предмета, сохранение, удаление с подтверждением.
- Новая работа создаётся черновиком.
- Две независимые версии содержимого: редактируемая и опубликованная. Автосохранение изменений опубликованной работы не должно сразу менять публичную страницу.
- Кнопка «Опубликовать» или «Обновить публикацию» атомарно копирует черновую версию заголовка, предмета и Markdown в опубликованную. Повторная публикация сохраняет URL.
- «Снять с публикации» немедленно закрывает публичную страницу и её вложения.
- Кнопка «Скопировать ссылку» и возможность открыть опубликованную страницу.
- Импорт одного UTF-8 .md-файла в редактор и экспорт текущего содержимого как .md. Картинки по относительным локальным путям автоматически не импортируются; объясни это в UI.

### 3.4. Markdown-редактор

- CodeMirror 6: подсветка Markdown, перенос длинных строк, undo/redo, удобный Tab в коде, доступная клавиатурная навигация.
- Режимы «Редактор», «Предпросмотр», «Рядом». На узком экране показывать только один режим за раз.
- Минимальная панель: заголовок, жирный, курсив, ссылка, список, блок кода, картинка. Действия вставляют Markdown в позицию курсора и сохраняют undo history.
- Ctrl+S / Cmd+S сохраняет; Ctrl+B / Cmd+B оборачивает выделение в **; Ctrl+I / Cmd+I — в *.
- Автосохранение примерно через 1 секунду после остановки ввода. Индикаторы: «Есть изменения», «Сохранение…», «Сохранено», «Ошибка сохранения».
- Не допускай гонок: последовательная очередь сохранений, номер revision на сервере и условное обновление. Старый ответ не помечает более новый текст сохранённым. При конфликте вкладок вернуть 409 и сохранить локальный текст для восстановления, не перетирать чужую версию.
- При уходе со страницы предложи сохранить или предупреди о несохранённых данных. Сбой сети не должен очищать редактор.
- Восстановление несохранённого текста из локального хранилища: по ID страницы и revision; при открытии предложить восстановление, не применять устаревший текст молча. При logout очистить локальные копии черновиков.
- Обычный Markdown — канонический формат. Не добавляй wiki-ссылки, плагины Obsidian, граф заметок и собственные блоковые JSON-документы.
- Live Preview с сокрытием разметки на неактивных строках НЕ входит в обязательный MVP. Не заявляй его поддержку, если реализован только split preview.

### 3.5. Изображения и вложения

- Вставка изображения из буфера Ctrl+V / Cmd+V, drag-and-drop и кнопка выбора файла.
- Захватывай только файловое изображение; вставка обычного текста должна работать стандартно.
- Загрузка привязывается к текущей работе; после успеха в исходную позицию вставляется `![описание](/media/UUID)`. При изменении текста во время загрузки корректно отобрази позицию через транзакции CodeMirror либо дай безопасный явный fallback. При переключении страницы результат не вставляется в другую работу.
- Показывай загрузку и понятную ошибку. До успеха не вставляй несуществующий окончательный URL. В базе и Markdown не хранить base64/data URL.
- Разрешить PNG/JPEG/WebP, максимум 10 MiB на изображение. SVG и HTML не принимать как изображения. Проверять сигнатуру и декодируемость, ограничивать число пикселей и суммарную параллельность декодирования. Можно проверять в spawn_blocking; перекодирование и генерация миниатюр не обязательны для MVP.
- Вложения: PDF, DOCX, TXT, MD, ZIP, максимум 50 MiB. Скачивание через Content-Disposition: attachment и X-Content-Type-Options: nosniff. Не распаковывать ZIP на сервере.
- Один файл на запрос. Явно настроить лимиты Axum и reverse proxy с запасом на multipart; JSON ограничить отдельно. Превышение возвращает 413, не generic 500.
- Передавать файл на диск порциями, проверять фактическое количество байтов. Не загружать весь ZIP в Vec. Использовать временный файл и атомарное перемещение после проверки. Удалять временные файлы при ошибке/прерывании.
- Физическое имя генерировать на сервере; пользовательское имя только для отображения/скачивания, очищенное от CR/LF. Запретить обход путей. Чтение только по UUID из базы.
- Не раздавать uploads как общедоступный static-каталог. GET /media/:id проверяет страницу-владельца и опубликованный набор вложений.
- Анониму доступны только файлы, вошедшие в текущий опубликованный снимок страницы. Новая картинка в черновике опубликованной работы остаётся закрытой до повторной публикации. Существующие опубликованные файлы доступны до замены публикации. Отношение page_public_assets пересчитывать транзакционно из ссылок Markdown и списка вложений при публикации.
- В MVP физическое удаление неиспользуемых файлов можно отложить; не удалять файл, пока он нужен опубликованной версии.

## 4. Дизайн

Спокойный интерфейс в стиле Notion, без копирования брендинга: светлый тёплый фон, тонкие границы, приглушённый текст, один сдержанный акцент. Слева sidebar примерно 250 px; по центру статья max-width 850 px. В режиме «Рядом» рабочая область шире. Никаких огромных рекламных заголовков, градиентных карточек и фоновых анимаций.

Sidebar: название сайта, поиск, предметы, работы; внизу вход/выход. Верхняя строка: хлебные крошки и действия. Основная часть: крупный заголовок, метаданные и текст. Кнопки публикации только в режиме автора. Для статьи — системный sans-serif, для команд — системный monospace; подключение внешних шрифтов не требуется.

На телефоне sidebar открывается кнопкой, таблицы и код имеют собственный горизонтальный скролл, вся страница не вылезает за viewport. Светлая тема обязательна; тёмная — улучшение после MVP. Видимый focus, aria-label для кнопок-иконок, контраст и управление с клавиатуры обязательны.

## 5. Данные и API

Минимальная модель, которую разрешено уточнять без изменения поведения:

- subjects: id, name, position, timestamps.
- pages: id, draft_subject_id, draft_title, draft_markdown, revision, timestamps.
- publications: page_id, subject_id, title, markdown, published_revision, published_at.
- assets: id, page_id, stored_name, original_name, mime, byte_size, kind, created_at.
- page_public_assets: page_id, asset_id; файлы текущей публикации.
- admin: id, username, password_hash.
- sessions: token_hash, admin_id, expires_at.

Отдельная таблица publications обеспечивает независимость черновика и публичного снимка. При публикации сохранять также выбранные вложения. Не использовать одну строку body и один флаг published для обеих версий.

Публичные маршруты:

| Метод и путь | Назначение |
| --- | --- |
| GET /api/public/subjects | Предметы с опубликованными работами |
| GET /api/public/pages?subject_id=&q=&limit=&offset= | Каталог/поиск с пагинацией |
| GET /api/public/pages/:id | Только опубликованный снимок |
| GET /media/:id | Изображение/скачивание с проверкой видимости |
| GET /healthz | Проверка готовности без секретов и путей |

Авторские маршруты под /api/admin:

- POST /login, POST /logout, GET /me.
- CRUD /subjects и /pages; чтение здесь возвращает черновик и состояние публикации.
- PATCH /pages/:id принимает expected_revision, возвращает новую revision; при конфликте 409.
- POST /pages/:id/publish принимает expected_revision и список публикуемых вложений, проверяет их владельца.
- DELETE /pages/:id/publication снимает публикацию.
- POST /pages/:id/assets загружает файл.
- GET /pages/:id/assets показывает вложения автору.

JSON-ошибки одного формата: `{ "error": { "code": "...", "message": "..." } }`. Валидировать длину заголовка, размер Markdown, пагинацию и MIME. Административные ответы и черновики не кэшировать. Неизвестные /api/* и /media/* не направлять в SPA fallback. Прямое открытие /p/:id и /admin/pages/:id/edit должно работать после перезапуска.

## 6. Минимальные требования к безопасности и ресурсам

- Все изменения, публикации и загрузки защищены серверной авторизацией; исключение — вход.
- Для cookie-auth применять проверку Origin на изменяющих запросах и CSRF-токен для авторизованных изменений. CORS в production не открывать; фронтенд и API на одном origin. В development настроить Vite proxy.
- Raw HTML в Markdown отключён. Результат рендеринга санитизируется; запрет javascript: и опасных data: URL. Одинаковые настройки в чтении и предпросмотре. Не писать собственный regex-санитайзер.
- SQL только параметризованный; сообщения пользователю не содержат SQL, паролей, cookie, полных путей и stack trace.
- SQLite WAL, busy timeout, небольшой пул соединений, внешние ключи включены. Проверки конфликтов и публикация транзакционны.
- Редактор загружается динамически только для автора. Не импортировать CodeMirror в публичный bundle по общему пути.
- Ограниченный список результатов поиска, lazy-loading картинок, debounce предпросмотра; CodeMirror уничтожается при уходе со страницы.
- Не добавлять неограниченный кеш страниц и файлов. Ограничить параллельные загрузки и тяжёлые операции.
- Измерить release-процесс: RSS после старта/простоя и при чтении/загрузке; зафиксировать команду, окружение и результаты. Желательная инженерная цель — idle RSS до 100 MiB для маленькой базы, но это не обещание и не критерий, ради которого ломают функции. Argon2 и проверка изображений создают пики: измерить их отдельно.
- Не путать размер Docker-образа, RAM бэкенда и RAM вкладки. Dev-серверы и сборщики не включать в оценку production.

## 8. Последовательность реализации

1. Осмотреть репозиторий и доступные Rust/Node/Docker. Выбрать совместимые stable-зависимости. Создать минимальный backend + Svelte/Vite и healthz. Сразу проверить сборку.
2. Реализовать миграции, первого администратора, сессии и права API. Проверить вход/выход и недоступность изменений анониму.
3. Реализовать предметы, черновики и независимые публикации. Проверить основную цепочку через API до усложнения интерфейса.
4. Сделать layout, каталог и страницу чтения, затем авторский CRUD. Данные должны идти из реального API.
5. Подключить CodeMirror, предпросмотр, последовательное автосохранение, ручное сохранение и обработку конфликтов.
6. Добавить загрузки, вставку скриншотов, скачивание и проверки видимости файлов.
7. Добавить поиск, оглавление, копирование команд, импорт/экспорт Markdown и адаптивность.
8. Собрать production frontend; настроить раздачу из Rust, Docker multi-stage и постоянный volume. Проверить перезапуск и прямые URL.
9. Выполнить проверки, исправить ошибки, записать результат и точные инструкции. Только после этого переходить к необязательным улучшениям.

## 9. Проверки готовности

Автоматизируй значимые серверные сценарии через временную SQLite и временное файловое хранилище. UI проверь в браузере; при доступном Playwright добавь один сквозной smoke test вместо десятков формальных тестов компонентов.

- Аноним не может создать, изменить или загрузить файл; черновик отсутствует в каталоге и поиске.
- Автор входит, создаёт предмет и страницу, пишет Markdown, сохраняет и после обновления видит тот же текст.
- Скриншот вставляется, сохраняется после перезапуска и виден в предпросмотре.
- До публикации прямые URL страницы и её файла закрыты анониму.
- После публикации страницу и нужные вложения видно в чистом браузерном контексте без cookie автора.
- Редактирование опубликованной страницы не меняет публичный текст и не раскрывает новые картинки. Повторная публикация обновляет их по прежнему URL.
- Снятие публикации закрывает страницу и файлы анониму.
- Старый expected_revision возвращает 409; несохранённый текст пользователя не теряется.
- Загрузка выше лимита возвращает 413; filename с ../ не выходит из каталога; псевдоизображение отвергается.
- Markdown с HTML, обработчиком onerror и javascript: ссылкой не исполняет скрипты ни в предпросмотре, ни в чтении.
- PDF/ZIP скачиваются как вложения. После перезапуска Docker данные сохраняются.
- Виды на ширине 390 px и 1440 px пригодны для использования. /p/:id открывается напрямую.
- Фронтенд проверен typecheck и production build. Rust: cargo fmt --check, cargo clippy --all-targets -- -D warnings, cargo test, cargo build --release. Укажи фактически запущенные команды. Если проверка заблокирована средой, не называй её пройденной.

## 10. Запуск и передача пользователю

Dockerfile: отдельные стадии Node-сборки, Rust-сборки и минимального runtime. Сборщики не входят в конечный образ. Runtime работает непривилегированным пользователем; директория данных доступна ему для записи. Проверь совместимость системных библиотек runtime с собранным бинарником.

Compose: сервис app, restart: unless-stopped, healthcheck доступной в runtime командой, постоянный volume /app/data. Для локальной проверки публикуй только 127.0.0.1:8080. Поля конфигурации: APP_HOST, APP_PORT, APP_BASE_URL, DATA_DIR, DATABASE_URL, COOKIE_SECURE, ADMIN_USERNAME, ADMIN_PASSWORD. Секреты не вшивать во frontend и образ.

Обязательные инструкции в README:

1. Требования и точные версии инструментов.
2. Создание .env и первого администратора без пароля по умолчанию.
3. Запуск `docker compose up -d --build`; если Docker недоступен, проверенный ручной запуск Rust и Vite.
4. Адрес http://localhost:8080, вход, создание работы, вставка картинки, публикация.
5. Просмотр логов, остановка, обновление без потери данных и явная смена пароля.
6. Резервная копия: самый простой корректный способ — остановить app и скопировать весь volume с базой и файлами, затем запустить; показать и восстановление. Не советовать копировать только live .sqlite без WAL.
7. Публикация на своём VPS: DNS A/AAAA на публичный IP, Caddy перед приложением для HTTPS, порты 80/443, COOKIE_SECURE=true и корректный APP_BASE_URL. Привести пример Caddyfile и различить хостовой и контейнерный upstream. База и внутренний порт не должны быть доступны извне.
8. Домен не заменяет хостинг; на GitHub Pages нельзя запустить Rust-бэкенд. У домашнего ПК возможен CGNAT, и DNS сам по себе эту проблему не решает.

Не регистрируй домен и не публикуй сайт автоматически. Для тестирования достаточно localhost; для друзей нужен постоянно работающий доступный сервер.

В итоговом сообщении дай: что работает, где запущено, как войти без вывода пароля, что проверено, что осталось. В STATUS.md запиши эти же сведения и измерения ресурсов. Никаких моковых API, фиктивных кнопок и заявления «готово» при неработающем сохранении.

## 11. Только после завершения MVP

Порядок возможных улучшений: тёмная тема; оптимизация картинок; Live Preview через CodeMirror decorations для заголовков/выделения/ссылок; история версий. Live Preview не должен ломать выделение, undo, IME и копирование исходного Markdown. Полное повторение Obsidian не является целью.

Не включать: регистрацию читателей, комментарии, совместное редактирование, WebSocket, базы Notion, slash-меню блоков, плагины, граф заметок, AI-функции, S3 и хранение гигабайтных образов ВМ в памяти.
