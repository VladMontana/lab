**Дата отчета**: 2026-11-14  
**Версия**: 0.1.0 (MVP)  
**Статус**: Готов к эксплуатации и финальной сертификации E2E

## 1. Состояние реализации MVP

Платформа LabNotes реализована в строгом соответствии со спецификацией `AGENT_PLAN.md` и архитектурой `PROJECT.md` в виде единого процесса без избыточных слоев абстракций.

### 1.1 Реализованные и проверенные функции
- **Единый бинарный сервис (Single-Binary)**: Сервер на Rust (Axum 0.8) одновременно обслуживает API (`/api/*`), защищенные медиапотоки (`/media/*`) и собранный Svelte SPA с маршрутизацией на стороне клиента (SPA fallback на `index.html`).
- **Изоляция 404**: Несуществующие маршруты под `/api/*` и `/media/*` строго возвращают унифицированный JSON-ответ `404 Not Found` и никогда не отдают HTML-оболочку фронтенда. Защита от выхода за пределы директории (Path Traversal) активна на 3 уровнях защиты.
- **Каталог и чтение материалов**:
  - Плоский каталог предметов и опубликованных работ.
  - Мгновенный регистронезависимый SQL-поиск по заголовкам и содержимому с экранированием метасимволов.
  - Полнофункциональный рендеринг Markdown: заголовки H1-H6, списки, чек-листы, таблицы, цитаты, блоки кода.
  - Кнопка копирования кода в буфер обмена с визуальной индикацией.
  - Автоматическое оглавление (TOC) по заголовкам H2 и H3 с плавной навигацией.
  - Полноэкранный просмотр изображений (Lightbox) с закрытием по клику или клавише `Escape`.
  - Список вложений для скачивания с корректными заголовками `Content-Disposition: attachment`.
- **Авторизация и безопасность автора**:
  - Единственная учетная запись администратора без пароля по умолчанию.
  - Хеширование паролей Argon2id вне асинхронного пула через `tokio::task::spawn_blocking`.
  - Защита от перебора паролей (Rate Limiter: блокировка после 5 неудачных попыток на IP-адрес).
  - Серверные сессии в SQLite со случайными токенами, хранящимися в виде SHA-256 хеша.
  - Cookie: `HttpOnly`, `SameSite=Lax`, флаг `Secure` в HTTPS-режиме.
  - Проверка заголовка `Origin` и токена `X-CSRF-Token` на всех мутирующих запросах.
  - Строгая санитизация Markdown через `markdown-it` (с флагом `html: false`) и `DOMPurify` — полное исключение XSS-векторов (`javascript:`, `data:`, обработчиков `onerror`).
- **Управление контентом и двухфазная публикация**:
  - CRUD для предметов и практических работ.
  - Защита от удаления непустых предметов (HTTP 409 `SUBJECT_NOT_EMPTY`).
  - Редактор CodeMirror 6 с динамической изоляцией бандла (публичные читатели не скачивают код редактора).
  - Автосохранение черновика через 1 секунду после окончания ввода с защитой от гонок сохранения.
  - Оптимистическая блокировка ревизий: HTTP 409 `REVISION_CONFLICT` при несовпадении `expected_revision` с сохранением локального текста в `localStorage` и модальным окном разрешения конфликта.
  - Независимые версии: редактирование опубликованной работы сохраняется только в черновике; публичная версия `/p/:id` и вложения не меняются до нажатия «Обновить публикацию».
  - Мгновенный отзыв доступа (404) для анонимов при нажатии «Снять с публикации».
- **Медиафайлы и загрузка**:
  - Вставка скриншотов через `Ctrl+V` и перетаскивание `Drag-and-Drop`.
  - Потоковая запись файлов на диск во временные файлы порциями по 64 КиБ; отказ от буферизации больших файлов в RAM.
  - Валидация сигнатур (Magic Bytes) и габаритов изображений (PNG, JPEG, WebP до 10 МиБ).
  - Вложения (PDF, DOCX, TXT, MD, ZIP до 50 МиБ).
  - Строгий отказ в загрузке SVG (`SVG_NOT_ALLOWED`) и исполняемых файлов. Превышение лимитов возвращает корректный HTTP 413 `FILE_TOO_LARGE`.
- **Контейнеризация и оркестрация**:
  - Многостадийный `Dockerfile` (сборщики Node и Rust не включены в runtime-образ).
  - Runtime запускается от непривилегированного пользователя `appuser` (UID 10001).
  - `compose.yaml` с постоянным томом `/app/data`, проверкой здоровья `/healthz` и безопасной привязкой только к `127.0.0.1:8080`.

### 1.2 Используемые сетевые порты
- `127.0.0.1:8080` — основной production-порт единого сервиса LabNotes (HTTP REST API, media, SPA).
- `http://localhost:5173` — порт dev-сервера Vite (используется только в режиме локальной разработки).

### 1.3 Процесс первого входа автора
1. Перед стартом в файле `.env` задается `ADMIN_PASSWORD` (в `.env.example` оставлен пустым).
2. При первом запуске на чистой базе данных бэкенд автоматически создает пользователя `admin` с хешем Argon2id.
3. Вход выполняется по адресу `http://localhost:8080/admin/login` (или через кнопку «Вход» в сайдбаре).
4. Явная смена пароля в процессе эксплуатации осуществляется командой:
   `docker compose exec app /app/backend --set-admin-password "НовыйПароль"`

## 4. Ограничения текущей версии и планы развития

### 4.1 Осознанные ограничения MVP
В соответствии со спецификацией `AGENT_PLAN.md` в платформу намеренно не включались нецелевые усложнения:
- **Один автор**: Система рассчитана на одного автора-преподавателя; регистрация читателей, роли и права комментирования отсутствуют.
- **Хранение данных**: Файлы и база хранятся на локальном томе сервера; внешние распределенные хранилища (AWS S3, MinIO) не используются.
- **Предпросмотр**: Реализован классический и надежный split preview (режимы «Редактор», «Предпросмотр», «Рядом»); сложный режим Live Preview с сокрытием синтаксических меток на лету не входит в объем MVP.
- **Протокол взаимодействия**: Используется стандартный HTTP/REST с debounce-сохранением; протоколы постоянных соединений (WebSocket, WebRTC) для монопольного автора не требуются.

### 4.2 План дальнейших улучшений (Post-MVP)
1. Добавление переключателя темной темы оформления (Dark Mode) с сохранением выбора в `localStorage`.
2. Фоновая оптимизация загружаемых растровых изображений (сжатие в WebP с сохранением оригиналов и генерация легковесных миниатюр).
3. Просмотр истории изменений черновика и отображение визуального diff перед повторной публикацией.
4. Экспорт статей в формат PDF средствами браузера со специальной печатной CSS-темой.
